# Contribuindo

- Use branches `feat/`, `fix/`, `docs/` e `chore/`.
- Prefira pull requests para mudanças estruturais.
- Toda funcionalidade precisa de testes e documentação atualizada.
- Mudanças de schema devem usar migrations versionadas.
- Mudanças de autorização precisam de testes negativos entre tenants.
- Não envie `.env`, tokens, chaves privadas, dumps ou dados reais de clientes.
